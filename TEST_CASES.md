### REST

#### Получение всех проектов
Эндпоинт: ```/push-console/api/v1/projects```

Метод: ```GET```

Позитивные тест-кейсы:
- Проверка успешного получения всех проектов с валидным _access_token_
- Проверка успешного получения всех проектов с только что созданным проектом в ответе

Негативные тест-кейсы:
- Проверка неуспешной попытки получения всех проектов с невалидным / пустым _access_token_

#### Создание проекта
Эндпоинт: ```/push-console/api/v1/projects```

Метод: ```POST```

Позитивные тест-кейсы:
- Проверка успешного создания проекта с допустимой длиной _name_
- Проверка успешного создания проекта с _name_, состоящим только из спец. символов
- Проверка успешного создания проекта с _name_, состоящим из букв кириллицы
- Проверка успешного создания проекта с _name_, состоящим из цифр
- Проверка успешного создания проекта с _name_, состоящим из букв в верхнем регистре

Негативные тест-кейсы:
- Проверка неуспешной попытки создания проекта с недопустимой длиной _name_
- Проверка неуспешной попытки создания проекта с _name_, состоящим из невалидных символов (другой язык)
- Проверка неуспешной попытки создания проекта с уже существующим _name_
- Проверка неуспешной попытки создания проекта с невалидным / пустым _access_token_
- Проверка неуспешной попытки создания проекта с невалидным типом _name_
- Проверка неуспешной попытки создания проекта с лишним полем в теле запроса
- Проверка неуспешной попытки создания проекта с пустым телом запроса
- Проверка неуспешной попытки создания проекта с другим полем в теле запроса

#### Получение всех приложений в проекте
Эндпоинт: ```/push-console/api/v1/projects/{id}/apps```

Метод: ```GET```

Позитивные тест-кейсы:
- Проверка успешного получения всех приложений в проекте, при условии отсутствия приложений
- Проверка успешного получения всех приложений в проекте, при условии существования одного приложения

Негативные тест-кейсы:
- Проверка неуспешной попытки получения всех приложений с несуществующим _id_ проекта
- Проверка неуспешной попытки получения всех приложений с невалидным / пустым _access_token_

#### Создание приложения
Эндпоинт: ```/push-console/api/v1/projects/{id}/apps```

Метод: ```POST```

Позитивные тест-кейсы:
- Проверка успешного создания приложения с допустимой длиной _name_
- Проверка успешного создания приложения с _name_, состоящим только из спец. символов
- Проверка успешного создания приложения с _name_, состоящим из букв кириллицы
- Проверка успешного создания приложения с _name_, состоящим из цифр
- Проверка успешного создания приложения с _name_, состоящим из букв в верхнем регистре

Негативные тест-кейсы:
- Проверка неуспешной попытки создания приложения с недопустимой длиной _name_
- Проверка неуспешной попытки создания приложения с несуществующим _id_ проекта
- Проверка неуспешной попытки создания приложения с _name_, состоящим из невалидных символов (другой язык)
- Проверка неуспешной попытки создания приложения с _package_name_, содержащим невалидные символы
- Проверка неуспешной попытки создания приложения с _package_name_, начинающемся с валидных символов, недопустимых в самом начале
- Проверка неуспешной попытки создания приложения с _package_name_, не содержащим периодов, т.е. символов '.'
- Проверка неуспешной попытки создания приложения с _package_name_, содержащим зарезервированные имена
- Проверка неуспешной попытки создания приложения с невалдиным _app_signature_
- Проверка неуспешной попытки создания приложения с уже существующим _name_ или _package_name_
- Проверка неуспешной попытки создания приложения с невалидным / пустым _access_token_
- Проверка неуспешной попытки создания приложения с невалидным типом _name_ / _package_name_ / _app_signature_
- Проверка неуспешной попытки создания приложения с лишним полем в теле запроса
- Проверка неуспешной попытки создания приложения с отсутствующим в теле запроса полем _name_ / _package_name_ / _app_signature_
- Проверка неуспешной попытки создания приложения с пустым телом запроса

### gRPC

#### Удаление приложения из проекта

Эндпоинт: ```/kc_push_console_v1.Delete/DeleteApp```

Метод: ```DeleteApp```

Позитивные тест-кейсы:
- Проверка успешного удаления приложения в существующем проекте

Негативные тест-кейсы:
- Проверка неуспешной попытки удаления приложения с несуществующим _access_token_
- Проверка неуспешной попытки удаления приложения с пустым _access_token_
- Проверка неуспешной попытки удаления приложения с невалидным  _access_token_
- Проверка неуспешной попытки удаления приложения с несуществующим _id_ проекта
- Проверка неуспешной попытки удаления приложения с пустым _id_ проекта
- Проверка неуспешной попытки удаления приложения с невалидным _id_ проекта
